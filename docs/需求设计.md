# DocSeek 需求设计

## 1. 产品定位

DocSeek 是一个本地运行的命令行工具，帮助 AI Coding Agent 从项目文档中定位相关文件、标题层级和行号。检索结果以导航信息为主，Agent 根据定位结果自行读取 Markdown 原文。

核心原则：**Retrieval is navigation, not context generation.**

## 2. MVP 目标

MVP 需要完成以下闭环：

1. 在当前项目中初始化本地索引。
2. 扫描 Markdown 文件并识别标题层级。
3. 按章节和自然段生成可检索片段，保存准确行号。
4. 使用本地 Embedding 与 SQLite FTS5 建立混合索引。
5. 接收自然语言问题，返回最相关的文件、章节和行号。
6. 文档变化后只处理新增、修改和删除的文件。

## 3. 使用者与典型流程

主要使用者是能够执行 shell 命令的 AI Coding Agent，也兼顾开发者手工调试。

```text
Agent 提问
  -> docseek search
  -> 混合检索
  -> 文件 + 标题层级 + 行号
  -> Agent 读取原始 Markdown
```

DocSeek 不依赖特定 Agent、编辑器或协议。

## 4. MVP 命令

### 4.1 `docseek init`

- 向上查找已有 `.docseek/config.toml` 或 Git 项目根目录。
- 无 Git 项目时使用当前目录，并给出提示。
- 创建 `.docseek/config.toml` 和 `.docseek/index.db`。
- 向项目根目录 `.gitignore` 添加 `/.docseek/`。
- 完整扫描配置中的 Markdown 来源。
- 解析标题层级、生成 Embedding、写入向量和 FTS5 索引。
- 新索引构建成功后再替换旧索引，避免失败时破坏可用数据。

### 4.2 `docseek update`

- 根据文件内容哈希识别新增、修改和删除。
- 未变化文件不重新解析，也不重新生成 Embedding。
- 更新结束后记录索引时间和统计信息。
- 模型配置与现有索引不兼容时，提示重新执行 `init`。

### 4.3 `docseek status`

- 显示项目根目录、索引模型、文档数、片段数和最近更新时间。
- 显示待处理的新增、修改和删除数量。
- 不加载 Embedding 模型。

### 4.4 `docseek search <query...>`

- 一个或多个查询参数会合并为一次自然语言查询。
- 支持 `--top <数量>`、`--path <路径>`、`--json`、`--snippet`、`--explain`。
- 默认不限制最终返回条数，召回候选池仍由本地配置控制；传入 `--top` 时按全局分数截断。
- 默认文本把共同目录、文件和标题层级合并为树，只在叶子显示行区间。
- 根节点只显示共同路径；有多个后代结果的目录、文件和章节显示命中片段数与平均分；只有一条结果的连续路径合并后直接显示行区间与分数。
- 默认只输出分数、文件路径、行号和标题层级。
- `--snippet` 只提供短片段，供人类调试。
- `--json` 输出稳定的机器可读结构。
- `--explain` 显示语义、关键词、融合和阶段耗时，只用于调试，不改变默认输出。

```json
{
  "results": [
    {
      "path": "docs/architecture/engine.md",
      "start_line": 142,
      "end_line": 176,
      "heading": ["Architecture", "Engine", "Scheduler", "Scale-out Policy"],
      "score": 0.92
    }
  ]
}
```

`score` 表示绝对检索强度，范围为 0 到 1，不表示命中概率，也不会因为某条结果排第一就固定为 1。

## 5. 文档发现与分块

- 默认来源是项目根目录，默认包含 `**/*.md`。
- 默认排除 `.git`、`.docseek` 和 `node_modules`。
- Markdown 标题建立父子层级，片段保存完整标题路径。
- 普通章节按章节边界切分。
- 超长章节再按自然段、列表、代码块等块级结构切分。
- 每个片段保存来源、文档位置、标题层级、起止行、内容哈希和内部正文。
- 默认搜索输出不返回内部正文。
- 相同路径和标题前缀在默认输出中只出现一次。

## 6. 检索要求

- 向量检索负责同义表达和自然语言语义。
- FTS5 负责项目专有名词、英文标识符和精确关键词。
- 中文内容增加分词和连续双字索引，弥补 FTS5 默认中文切词能力。
- 两路结果使用稳定的排名融合算法合并。
- 精确词项覆盖可以提升纯关键词候选，避免项目术语被模糊语义结果压制。
- 低可信候选可以全部被过滤；`--top` 表示最多返回多少条，不承诺凑满数量。
- 路径筛选在两路检索中都生效。
- 相同索引与查询应返回稳定顺序。
- 真实模型评测覆盖中文改写、精确术语、中英文混合、路径过滤和无答案问题。

## 7. 可扩展性约束

MVP 只开放当前项目的 Markdown 来源，同时保留下列稳定边界：

- 每个项目拥有独立的集合标识。
- 一个集合可以登记多个文档来源。
- 文档使用“来源标识 + 文档位置”形成稳定身份。
- 文档定位使用通用地址，文件路径只是 MVP 的展示形式。
- 标签与正文、Embedding 分开存储，修改标签不要求重新生成向量。
- 搜索请求内部可以表达集合、来源、标签和路径筛选。
- 配置文件和数据库都带版本号及迁移入口。

未来可以在这些边界上增加：

- `docseek add <目录或文件>`。
- `docseek add <路径> --tag <标签>`。
- 按来源或标签过滤、加权。
- 用户级全局索引和跨项目检索。
- 项目记忆等非文件来源。

这些能力不属于 MVP，不提供占位命令，也不出现在当前帮助信息中。

## 8. 非目标

- MCP、Web UI、后台服务和云端服务。
- 多用户、权限系统和对话记忆。
- 自动总结、自动修改文档和大段上下文拼装。
- Code RAG、知识图谱、复杂重排和 Agentic Retrieval。
- MVP 阶段的全局项目索引、外部目录和标签命令。

## 9. MVP 验收标准

- 新项目能通过 `init` 生成可用索引。
- 中文同义问题能命中相关章节。
- 项目专有名词能通过关键词检索命中。
- 输出包含准确文件路径、标题层级和行号。
- 默认输出不包含完整片段正文。
- `update` 不处理内容哈希未变化的文件，并能删除失效索引。
- `--json` 可以被程序稳定解析。
- 无后台进程、数据库服务或容器依赖。
- 格式化、严格类型检查、静态检查、单元测试、集成测试、构建和 npm 包检查全部通过。

## 10. Agent 全局使用入口

- 全局 npm 安装完成时，自动维护当前用户的 Codex 与 Claude 全局规则文件。
- Codex 目标为 `$CODEX_HOME/AGENTS.md`；未设置 `CODEX_HOME` 时使用 `~/.codex/AGENTS.md`。
- Claude 目标为 `$CLAUDE_CONFIG_DIR/CLAUDE.md`；未设置 `CLAUDE_CONFIG_DIR` 时使用 `~/.claude/CLAUDE.md`。
- 两个文件写入相同的精简提示词，告诉 Agent 何时搜索、如何组合概念、如何刷新索引以及如何读取原文。
- 提示词使用稳定的开始和结束标签。存在完整闭合区块时替换区块，不存在标签时追加整段。
- 文件只出现单边标签、标签顺序错误或标签重复时停止修改该文件，并显示不包含原文的警告。
- 保留标签外的全部内容、原换行风格和 UTF-8 BOM；拒绝直接改写符号链接文件。
- 两个目标独立处理，一个失败时继续处理另一个；提示词注入失败不阻止 DocSeek CLI 安装。
- 本地项目依赖安装不修改用户全局规则，只有全局安装触发生命周期注入。
- 提供 `docseek instructions` 查看提示词，以及 `docseek instructions --install` 手工重新注入，供 npm 禁用安装脚本或用户修复时使用。
- DocSeek 建立 Markdown 索引时屏蔽自己生成的标签区块，并保留相同行数，避免使用说明参与项目语义召回或改变后续位置。

## 11. 建库性能优化

- 大型文档目录的主要等待时间应能拆分为扫描、分块、模型加载、向量生成和数据库写入，便于确认真实瓶颈。
- 本地向量化方案需要使用同一批文档片段和同一批查询做公平对比。
- 首次模型下载单独记录，不计入温缓存建库时间；下载大小和成功率仍属于安装成本。
- 检索效果必须先达到 M4 的质量门槛，未达标的方案不因速度快而进入正式实现。
- 达标方案继续比较完整建库耗时、片段处理速度、查询延迟、峰值内存、包体积和跨平台安装难度。
- 性能评测代码与候选依赖放在独立目录，不进入正式 npm 包；只有最终选中的方案接入产品代码。
- M7 以 InferForge 的 126 份 Markdown、1,598 个片段作为首个固定规模样本，温缓存完整建库相对约 240 秒基线至少缩短 50%。
- 如果候选方案都未同时达到质量和性能门槛，保留当前实现并继续评测，不为完成里程碑强行切换。
