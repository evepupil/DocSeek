# 项目与配置模块

- **模块定位**：发现当前项目并管理本地版本化配置。
- **对应代码**：`src/project/`、`src/config/`、`src/sources/`。
- **所属 M 里程碑**：[M0 工程基础](../roadmap.md#m0-工程基础)。
- **当前状态**：已完成。
- **最近更新时间**：2026-09-01。

## 职责与边界

- 从当前目录向上查找 `.docseek/config.toml` 或 `.git`。
- 初始化项目标识、Embedding、分块和来源配置。
- 维护根目录 `.gitignore` 中的 `/.docseek/`。
- 把来源配置转换为统一的文档发现接口。
- 不解析 Markdown，不生成 Embedding，不执行搜索。

## 结构与数据流

```text
当前目录
  -> 项目根目录发现
  -> 配置读取或创建
  -> 来源配置校验
  -> Markdown 目录来源
  -> DiscoveredDocument
```

MVP 只有项目根目录来源。来源接口已经允许绝对目录、单文件或其他内容提供者返回同一文档结构。

## 关键决策

- 配置放在 `.docseek/config.toml`，跟随本机索引整体忽略。
- 项目标识使用 UUID，方便未来登记进用户级全局集合。
- 来源拥有独立标识、类型、根路径、包含规则、排除规则和标签。
- 先查已有 `.docseek`，保证从项目子目录执行命令时使用同一索引。
- 配置版本不受数据库版本约束，两者分别迁移。

## 当前实现

当前已经实现：

- 从子目录向上发现已有 DocSeek 配置，再回退到 Git 根目录或当前目录。
- 使用严格校验的版本化 TOML 配置生成项目 UUID 和默认来源。
- 自动、幂等地维护 `/.docseek/` 忽略规则。
- 通过来源注册表发现一个或多个 Markdown 目录。
- 每个来源保存独立标识、路径规则和标签。
- 配置更新使用临时文件和可恢复替换。

集成测试已经验证两个来源可以进入同一索引、按来源标签搜索，并在移除来源后正确清理文档。

## 验证方式

- 在 Git 根目录和子目录中发现同一项目。
- 无 Git 时回退到当前目录。
- 重复初始化不重复写入忽略规则。
- 非法配置给出可操作错误。
- 来源排除 `.git`、`.docseek` 和依赖目录。
