# 混合检索模块

- **模块定位**：融合语义和关键词候选，返回稳定、可解释的文档定位结果。
- **对应代码**：`src/search/`、`src/application/search-docs.ts`。
- **所属 M 里程碑**：[M2 混合检索](../roadmap.md#m2-混合检索)。
- **当前状态**：已完成。
- **最近更新时间**：2026-09-01。

## 职责与边界

- 生成查询向量和 FTS5 查询词项。
- 获取向量与关键词候选。
- 使用加权排名融合生成最终顺序和分数。
- 应用路径、集合、来源和标签筛选。
- 返回定位结构，不读取或总结命中文档全文。

## 结构与数据流

```text
SearchRequest
  -> 查询 Embedding -> 向量候选
  -> 中英文词项     -> FTS5 候选
  -> 加权排名融合
  -> SearchResult[]
```

公开 CLI 当前只传查询、数量和路径。集合、来源、标签已经存在于内部请求结构，等待后续命令开放。

## 关键决策

- 向量与 FTS 分别取足量候选，再进行融合。
- 默认权重为向量 0.7、关键词 0.3，RRF 常数为 60。
- 标题在 BM25 中权重更高。
- 中文使用分词、双字组合和短词组共同召回。
- 最终并列时按来源、文档位置、行号和片段标识稳定排序。
- 分数归一化到 0 至 1，仅表示本次融合相关度。

## 当前实现

当前已经实现中英文和代码标识符词项、中文分词与双字组合、向量精确检索、FTS5 BM25 和加权排名融合。路径、集合、来源和标签筛选在存储查询中生效。最终结果按本次最高融合分数归一化，固定使用路径和行号打破并列。

真实查询“后续如何增加外部文档目录并打标签”将架构设计中的“外部文档”和“标签”排在前两位，并返回准确标题层级和行号。

## 验证方式

- 中文同义表达由向量路召回。
- 项目术语和代码标识符由 FTS 路召回。
- 同时命中两路的结果获得更高排名。
- 路径筛选不会返回范围外结果。
- 相同输入重复搜索顺序一致。
- 空索引和无结果查询正常返回。
