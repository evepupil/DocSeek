# 检索质量评测模块

- **模块定位**：用固定问题集衡量真实模型的定位质量、无答案行为、稳定性和搜索耗时。
- **对应代码**：`eval/search-quality.json`、`scripts/evaluate-search.mjs`、`src/evaluation/`、`src/search/`。
- **所属 M 里程碑**：[M4 检索质量](../roadmap.md#m4-检索质量)。
- **当前状态**：已完成。
- **最近更新时间**：2026-09-03。

## 职责与边界

- 保存问题、问题类型、期望文件和期望标题。
- 使用真实 Embedding 和当前 SQLite 索引运行检索。
- 计算前五命中率、第一名命中率、平均倒数排名、无答案识别率和稳定性。
- 记录模型加载与推理、向量查询、关键词查询、融合排序的耗时。
- 不保存文档答案，不参与生产搜索，不进入 npm 发布包。

## 结构与数据流

```text
固定问题集
  -> 更新 DocSeek 自身索引
  -> 复用一个真实模型会话
  -> 调用生产搜索执行入口
  -> 匹配文件与标题
  -> 汇总质量与耗时
  -> 达标或以非零状态退出
```

## 关键决策

- 首批问题以 DocSeek 自身文档为语料，覆盖本轮真实暴露的问题。
- 正向问题只保存定位期望，允许一个问题对应多个合理章节。
- README 结构调整后同步更新对应章节；设计问题仍以能解释实现的模块章节为期望，不用过时标题维持表面通过。
- 无答案问题选择与 DocSeek 明显无关的领域，避免把邻近技术主题误判为错误。
- 真实模型评测使用独立命令，不加入发布门禁。
- 单元测试固定候选和向量，真实评测负责发现模型与语料共同造成的偏差。
- 相同问题连续运行两次，结果路径、标题、行号和分数必须完全一致。

## 当前实现

当前问题集包含 24 条查询：14 条正向定位与 10 条明确无答案问题。正向查询覆盖中文语义改写、英文查询、精确术语和路径过滤。评测启动时先增量更新 DocSeek 自身索引，再复用一个真实模型会话完成预热、两轮查询和结果比较。问题清单使用运行时结构校验，指标计算和执行逻辑均纳入 TypeScript 严格检查，启动脚本只负责调用编译产物。

当前真实语料评测的五项门槛均已通过。正向问题前五命中率保持在 90% 以上，第一名命中率保持在 70% 以上；精确术语首位、无答案识别和重复查询稳定性均达到 100%。复用模型后的总耗时在本机多轮实测中位数约 18 至 28 毫秒，第 95 百分位约 27 至 63 毫秒，具体数值会随同时运行的进程负载波动。

显式 CLI 诊断显示单进程首次搜索主要耗时来自本地模型加载，实测约 1.7 秒；预热后向量生成、两路查询和融合都在毫秒级完成。保持零后台服务时接受该启动边界，后续模型选型变化时重新测量。

## 验证方式

- 正向问题前五命中率不低于 90%。
- 精确术语问题第一名命中率不低于 90%。
- 无答案识别率不低于 90%。
- 相同查询稳定性为 100%。
- 输出各阶段中位数和第 95 百分位耗时。
- 评测失败时列出具体问题和实际首条结果。
